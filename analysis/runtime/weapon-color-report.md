# Native weapon texture loading

White meshes are consistent with missing texture HTTP responses; mesh streaming and texture streaming are independent. Static evidence alone does not prove the live failure: inspect actual requests and the native `Failed to load texture.` message.

Weapon.SetSkin (function76812/table21441) prefixes skin names with `weapon-skins/texture/`. TextureLoader.InstanceGetTexture2DOf (function76630/table21230) constructs `https://kour.io/content/stream/` + key + `.png` + optional `?size=NxN`. The source MP5 prefab defaultSkinName is `mp5` (sharedassets0.assets object8325), AWP `awp` (object8423). Their native URLs therefore end in `/content/stream/weapon-skins/texture/mp5.png` and `/awp.png`. The method supplies filterMode0 and custom desktop/mobile sizes-1. The loader resolves settings/platform flags into size; compiled default/cap values include256 and64. Preserve the actual query in a local mirror; do not assume a single variant for all settings.

The texture coroutine function76655 calls UnityWebRequestTexture.GetTexture (table12217), SendWebRequest9072, result12220 and DownloadHandlerTexture.GetContent12221. Thus these dependencies are PNG images decoded by Unity, not raw Texture2D bytes or AssetBundle textures. Successful loads apply the requested filterMode and wrapMode; the texture cache avoids repeated downloads.

Weapon.ApplySkinTexture (function76813/table21442) rejects null with `Failed to load texture.`. For isTextureRaw=true it creates a new Standard material; otherwise it clones the configured custom material or first renderer material, assigns both `mainTexture` and `_MainTex`, then assigns Renderer.material. No shader/material rewrite is indicated when the native image request simply fails.

Beretta92fs (object8320) has empty defaultSkinName, no custom material and an empty weaponRenderers array. Shooter.SetWeapon74291 checks defaultSkinName for whitespace at23585495 and branches past SetSkin at23585499 when empty; RPCSetWeapon74345 repeats this guard at23631063..23631067. Therefore default Beretta retains its embedded materials and does not request error.png. The asset agent independently found no serialized LoadMyMaterialTexture on Beretta. No Beretta texture URL is established. For other prefabs, LoadMyMaterialTexture type4281 has private [SerializeField] `texturePath` field17837 at runtime+16. Start function77555 reads it at24704804 and sends it verbatim to GetTexture2DOf (no additional weapon-skins prefix). Its callback77556 uses Renderer.material.mainTexture. This independent component is not evidence of a Beretta dependency. Default Beretta should be diagnosed using live renderer material colors, mesh submesh count/order, and actual native lighting rather than a guessed PNG.

Minimal repair: mirror the original successful PNG responses locally and bridge only the exact native content paths to these local files, preserving requested image variants. Let original texture decoding, callbacks, cache and material assignment run. Retest each weapon after its asynchronous native callback. Source instruction artifacts are weapon-color-static.json, weapon-color-coroutine.json and weapon-color-material-loader.json. Metadata comes from gameplay.json and retained REA evidence; native instruction decoding is the local WASM parser.

## Applied repair and runtime evidence

The local server now serves the two original PNGs at their native content paths. It injects their explicit allowlist into the offline policy, which rewrites only these known legacy image URLs into local fetch/XHR URLs. Other original-service connections remain disabled. Optional valid size queries are preserved; local PNGs are the unresized original files. The actual tested desktop requests had no size query.

The parent visually inspected weapon-colors-mp5.png, weapon-colors-awp.png and weapon-colors-beretta.png. MP5 has a charcoal textured finish; AWP has an olive/dark textured finish. Their PNG requests returned local HTTP200. Default Beretta displays silver/gray parts, matching the three embedded gray Standard materials; it has no established missing PNG dependency.
